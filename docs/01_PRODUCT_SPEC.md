# 제품 기획서
버전 3.0 | 2026-10-22 | 이 문서 단독으로 제품 목적과 범위를 정의한다.

## 1. 목표
중국 소셜 플랫폼 微博·小红书·豆瓣에서 특정 사건/주제에 관한 공개 게시물과 댓글을 수집·입력하고,
조직적 행동의 근거, 콘텐츠가 플랫폼을 이동한 경로, 주장이 변한 과정, 운영·지시 주체의 공개 근거를 사람이 검토하게 한다.
제품은 조사 지원 도구다. 특정 계정/기업을 자동 범인으로 지목하는 기능은 제공하지 않는다.

주요 질문:
- 관측 범위에서 누가 언제 무엇을 게시했는가?
- 같은 공개 계정들이 우연보다 반복적으로 함께 움직였는가?
- 원문 URL·캡처·희귀 문구·이미지 편집 흔적으로 콘텐츠 차용을 확인할 수 있는가?
- 플랫폼 이동 중 원문에 없는 세부 내용·인과 연결·단정 표현이 추가됐는가?
- 공개 총공, 언론 보도, 방송 등 공통 원인으로 설명되는가?
- 운영 주체/의뢰인에 대한 별도 증거가 있는가? 무엇이 아직 미확인인가?

## 2. 플랫폼과 객체
| 플랫폼 | 핵심 대상 | 유의점 |
|---|---|---|
| 微博 | 원문, 재전파, 댓글/답글, 공개 계정, 热搜 | 공통 보드와 개인화 추천을 구분 |
| 小红书 | 노트 제목/본문/이미지/영상, 댓글/답글, 공개 계정 | 이미지 OCR와 캡처 속 시각을 업로드 시각과 분리 |
| 豆瓣 | 小组 주제/댓글, 영화 리뷰/短评 등 공개 객체 | group와 movie는 별도 수집 범위 |

사용자는 TikHub·JustOneAPI 유료 계정과 API 키를 보유한다.
문서상 웨이보/小红书 기능이 있어도 계정 권한·검색 완전성·과거 조회 범위는 실측 전 미확인이다.
豆瓣小组 API는 아직 확인되지 않았다. movie 기능으로 group 수집을 대체 완료하지 않는다.
세 플랫폼 공통 파일 입력은 초기부터 지원하며 실제 데이터/fixture/manual import를 표시한다.

## 3. 사용자 역할
관리자: 사용자·키·공급자·예산·보존 설정.
분석가: 사건·수집·분석·증거·가설 작성.
검토자: 근거·관계·보고서 검토 승인.
열람자: 허용된 사건의 결과 열람.
단일 조직 MVP. 사건별 권한 검사를 서버에서 수행한다.
분석가와 검토자 겸임은 가능하나 자체 검토임을 감사 기록에 표시한다.

## 4. 전체 흐름
사건 생성 → 플랫폼/surface·검색어·별칭·기간·씨앗 설정
→ 호출 없는 예산 추정 → 수집/파일 입력 → 품질 확인
→ 콘텐츠 군집/시간 순서/전파 후보/행동 반복 분석
→ 원문 대조·관계 승인 → 대안 가설 및 반대 증거
→ 검토 승인 보고서/근거 묶음.
시간대는 Asia/Shanghai, DB는 UTC. 한국어 UI와 중국어 원문을 기본으로 한다.

## 5. 판단 체계
| 축 | 결과 예 | 다른 판단과의 관계 |
|---|---|---|
| 조직성 | 반복 협조 패턴 관측/추가 검토/미판정 | 공개 팬덤 총공도 조직적일 수 있음 |
| 기만성 | 공개 활동 설명 있음/검증된 기만 근거/미확인 | 조직적이라는 이유만으로 기만적이지 않음 |
| 콘텐츠 관계 | 직접 참조/차용 후보/의미 유사/시간 선행만 | 전파·공동 운영과 구분 |
| 운영 귀속 | 공개 연관/운영 관계 검증/미확인 | 의뢰/지시 관계와 구분 |
| 의뢰·지시 | 직접 근거 검토/미확인 | 수혜·팔로우·입장 유사만으로 확정 불가 |
| 데이터 충분성 | 수집창·누락·시간 정밀도·기준선 상태 | 하나의 정확도 점수로 축약하지 않음 |

“공작 확률 92%” 같은 미검증 확률 표시 금지.
지표는 검토 우선순위와 원문 확인을 돕는다.
검색 표본의 비율을 전체 플랫폼의 비율로 일반화하지 않는다.
관측 첫 글은 “확보한 자료에서 가장 이른 게시물”로 표현한다.

## 6. 최초 내부 운영 버전 범위
필수:
- 인증·사건 권한·사건 CRUD.
- 3플랫폼 객체/시간/관측 모델, CSV/JSON 입력과 검증.
- 공급자별 기능 목록, 예산 추정·예약·수집·중단·재개·실패 표시.
- 검증된 微博/小红书 API 연동. 豆瓣 group 입력 및 향후 adapter 확장.
- 게시/수정/관측 시간을 구분한 3플랫폼 timeline.
- URL 직접 참조, 희귀 문구·매체 일치, 기본 OCR 기반 전파 후보.
- 주장 원문 구간 비교와 수동 변형 라벨; 자동 제안은 보조.
- 반복 동시 행동 후보 및 재현 가능한 우연 기준선.
- 콘텐츠 계보/행동 협조/공개 운영 관계를 별도 표시.
- 증거·가설·반대 증거·대안 설명·검토.
- 고정된 분석 입력과 보고서 버전, Markdown/HTML/CSV/JSON/ZIP 출력.
- 비용·수집 공백·비밀 관리·백업/복구 절차.

후속:
다사건 반복 계정군 비교, 장기 관찰, 의미 임베딩, 고급 영상 매칭,
선행·지연 통계 모형, PDF, 추가 데이터 공급자.
Granger/Hawkes는 선택 연구 기능이며 최초 버전의 완료 조건이 아니다.
실제 인과 효과 추정은 별도 식별 설계가 필요하고 단순 전후·시간 상관으로 대체하지 않는다.

제외:
비공개 메시지, 사적 연락처/주소 수집, IP·기기 추적, 실명 역추적,
계정 침입/로그인 우회, 자동 댓글/신고/여론 대응, 공개 배포/공표.
운영·의뢰인 근거는 공개 소속 자료 및 사용자가 적법하게 확보해 제공한 자료를 검토 기록으로 다룬다.

## 7. 화면
| 화면 | 기능과 완료 행동 |
|---|---|
| 사건 목록/설정 | 플랫폼별 검색어·제외어·기간·씨앗·외부 사건·예산 |
| 수집 계획/상태 | 공급자·기능·예상 호출·실행/중단/재개·실패 |
| 품질 | 플랫폼×surface×기간 누락/cap/정밀도·공급자 차이 |
| 통합 timeline | 세 플랫폼+공통 원인 행, 불확실 구간, 수정 표시 |
| 콘텐츠 계보 | 직접 참조와 차용 후보 구분, edge→근거→원문 |
| 콘텐츠/주장 비교 | 원문/인용/신규 의견/추측/부정/추가 내용 비교 |
| 계정군 | 행동별 연결·반복수·기대값·근거; 지휘자 명칭 없음 |
| 증거/가설 | 지지·반대·대안·미확인·검토 이력 |
| 보고서 | 분석 run 선택, 초안/승인·범위/한계·출력 |
| 운영 | 공급자 상태·예산·역할·보존·감사; 키 원문 숨김 |

그래프는 표 조회도 지원한다. 0/미수집/지원 안 됨/조회 실패는 다른 상태다.
필터로 그래프 일부만 표시하면 전체로 오해하지 않도록 표시 수·총수·필터를 명시한다.
原文, 캡처, OCR 결과, API 응답을 각각 다른 자료 종류로 표시한다.

## 8. 전파와 인과 표현
직접 URL 인용은 참조 관계의 증거이지 원문의 진실성이나 공동 지시 증거는 아니다.
동일 오타/편집 흔적은 차용 후보지만 미관측 공통 원본이 있을 수 있다.
시간 선행만 확인되면 화살표로 인과를 확정하지 않는다.
게시물의 현재 문구가 나중에 추가되었을 가능성이 있으면 생성 시각으로 차용 방향을 확정하지 않는다.
반박 인용은 긍정적 확산과 구분한다.
동일 닉네임·사진의 다른 플랫폼 계정을 자동 동일인으로 합치지 않는다.

가상 예:
小红书 원문 “지급이 늦어졌다” → 豆瓣 질문 “그래서 치료가 미뤄졌나?”
→ 微博 단정 “지급 지연 때문에 치료가 중단됐다”.
원문에서 확인되지 않는 인과 연결과 추측→단정 변화를 표시한다.
이는 기능 설명용 가상 자료이며 실제 인물에 관한 판정이 아니다.

## 9. 보고서
질문·기간 → 플랫폼별 수집 범위/누락 → 확인 사실 → 직접/추정 전파 경로
→ 조직성 근거 → 내용 변형 → 공통 원인/다른 설명
→ 운영/지시 가설과 반대 자료 → 미확인 → 증거 색인/재현 정보/검토자.
지표마다 분모·시간 범위·자료 종류를 표시한다.
승인한 보고서는 새 수집으로 바뀌지 않는다. 새 자료는 새 분석·보고서 버전으로 만든다.
원본 응답과 해시는 기록/무결성 수단이며 내용의 진실성·법적 증거능력을 자동 보증하지 않는다.
