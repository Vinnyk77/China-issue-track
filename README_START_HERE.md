# CPEL 개발 시작 키트
버전 3.0 | 2026-10-22 | 언어: 한국어 | 대상: 빈 저장소에서 개발하는 코딩 에이전트

이 패키지만으로 개발을 시작할 수 있다. 이전 대화, 웨이보 단독 기획서, v2 확장 문서는 필요하지 않다.
이전 코드가 존재한다는 가정이나 기존 스키마를 이전하는 절차도 없다.
제품: 微博·小红书·豆瓣의 공개 콘텐츠에서 조직적 확산과 플랫폼 간 전파 과정을 조사하는 내부용 웹 도구.
제품명: Cross-Platform Evidence Lab(CPEL).
현재 이 패키지는 기획·구현 지시 자료다. 실행 가능한 앱이나 검증된 API 연동 코드는 아직 없다.

## 시작 방법
1. ZIP을 풀고 CPEL_Development_Kit의 내용물을 개발할 저장소 루트로 복사한다.
2. 코딩 에이전트에게 prompts/00_START.md의 전체 본문을 전달한다.
3. 에이전트는 docs 문서를 읽고 M0부터 구현하며, 키가 없어도 테스트 데이터로 개발을 계속한다.
4. 중간에 대화를 바꾸거나 에이전트를 재시작하면 prompts/01_RESUME.md를 전달한다.
5. 실제 연동 시 서버 환경에 키·호출 예산을 설정하고 prompts/02_LIVE_INTEGRATION.md를 사용한다.
6. 파일럿과 인수 검토에는 prompts/03_ACCEPTANCE.md를 사용한다.

처음부터 모든 프롬프트를 한 번에 보낼 필요는 없다. 00_START가 전체 개발 방향과 진행 규칙을 포함한다.
프롬프트는 단계별 사용을 돕는 구성이다. 단계가 끝날 때마다 사용자에게 다시 허가를 받으라는 뜻은 아니다.
사용자가 정한 범위에서 다음 작업을 계속하되, 키·실제 예산처럼 필수 값이 없으면 해당 연동만 보류한다.

## 문서 권한과 충돌 처리
- 제품 요구·해석: 01. DB/알고리즘/API 계약: 02. 구현 순서·단계 범위: 03.
- 테스트: 04. 외부 공급자 경로/권한/제한: 05와 실제 최신 공급자 문서.
- 파일 입력: 06. 저장소 작업: AGENTS.md.
- 예전 문서보다 이 패키지를 기준으로 구현한다. 예전 문서를 가져와 부록 우선순위를 따질 필요가 없다.
- 사용자 새 지시를 우선하고, 변경된 요구는 관련 문서·테스트·상태 파일에 함께 반영한다.
- 구현 선택이 필요한 경우 ADR에 이유를 남기고 진행한다. 외부 API를 추측해 만드는 것은 구현 선택이 아니다.

## 지금 필요한 준비
빈 저장소와 Docker를 사용할 수 있는 개발 환경이면 M0~M5 개발을 시작할 수 있다.
TikHub·JustOneAPI 유료 계정은 이미 보유한 것으로 가정한다. 키 값과 실제 요금·한도는 문서에 없다.
실제 호출 단계에서 키, 공급자별 호출/금액 한도, 조사 사건 키워드·기간·씨앗 URL이 필요하다.
豆瓣小组 수집 API는 미확인이다. 파일·URL 기반 수동 입력을 처음부터 지원해 세 플랫폼 비교를 막지 않는다.
시간 선후·콘텐츠 차용·예측 관계·인과 효과·공동 지시는 다른 판단이다.
